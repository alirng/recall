**recall's tools no longer fail with `database is locked`.** Since 0.4.0, on a machine with more than one Cursor build, every index refresh opened a write that nothing committed, and an agent's recall MCP server kept it open after its first tool call. Its later calls, and other agents' and hooks', waited 30 seconds for the index and failed. In the eval of questions about past work, a third of recall's tool calls failed this way. A refresh with nothing to write now writes nothing, a refresh commits what it wrote, and the chat and note tools close their connection to the index at the end of each call. Restart agents that were open when you upgrade, since their servers keep the release they started with.
