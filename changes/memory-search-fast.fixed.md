**memory_search no longer rebuilds the notes index on every call.** It used to drop and rebuild the notes tables and load every note twice per search, which took the index's write lock while other agents' servers were reading, so a search elsewhere could fail with a transient `vtable constructor failed` error. It now rebuilds only when a note file, the `[contexts]` in config.toml, or the tables' layout differs from what the index was built from, so a hand edit still shows up on the next search, and a rebuild is one transaction. With 733 notes and embeddings on, a search takes about 35 ms through the MCP server, against about 530 ms in 0.4.2. Servers still running an older release keep rebuilding the tables until their agent restarts.
