**`recall api` makes the few changes an app may make.** New endpoints edit a note (`PUT /v1/notes/{id}`, with `POST …/preview` to see what saving would record), forget one and put it back (`POST …/forget`, `POST …/restore`), set the coordination rules (`PUT /v1/coordination`), list the models that work here and switch to one after a test call (`GET /v1/models`, `PUT /v1/model`), and remove copies kept before an upgrade (`POST /v1/storage/remove`). Each runs recall's own code and takes the same notes lock as a memory run, answering `409 busy` while one runs and `409 conflict` when the note's file changed since the client read it. `/v1/info` lists them under `writes`, and `/v1/notes/{id}` gains `stamp`. Started by an app or launchd, `recall api` adds the nightly run's folders to its `PATH`, so it finds Claude Code, Codex and local model servers. See docs/api.md.
