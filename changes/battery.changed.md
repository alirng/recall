**recall waits for power on battery.** `recall dream` defers itself when it starts on battery, the nightly run included (launchd runs a missed night when the Mac wakes) and one typed at a terminal too: `recall dream --on-battery run` runs it anyway, and `on_battery = "run"` under `[power]` in config.toml lets everything run on battery. Tool calls start no background indexing or embedding on battery, and background jobs now run at low priority. `recall status` and `recall doctor` say when `recall dream` deferred. On Linux the systemd service also gets `ConditionACPower=true`, so systemd skips the run on battery without a record; run `recall schedule enable` again to add it to an existing timer, and after changing `on_battery`.
