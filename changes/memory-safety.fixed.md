**Memory that reaches an agent unasked no longer carries commands, links or other chats' prompts.** A README or web page an agent read could become a note that session start injected into every later session. Now a rule that asks for a command, a URL, a network, destructive or exfiltrating action, or for switching off a check never loads at session start or mid-session, and neither does a note with such a title; memory_search and read_note still find them. A rule only the agent stated shows by its note's title alone at session start, and mid-session hooks skip it. Every injected line is one capped line with tag-like text removed, so a note holding `</recall-memory>` cannot end the block early; rule pointers from other agents' files are capped the same way. On my chats, session start now loads 0.509 of the notes it must (was 0.576), 0.433 on held-out folders (was 0.488); most of what it drops is project facts written with a code span. `recall status` redacts a chat's title and latest request before caching them or quoting them to other chats, and its cache rebuilds once. The deletion ledger (`.recall/notes.json`) kept the start of every note's body, and consolidation sent 200 characters of each deleted note to the model: it now keeps the title, scope and project, existing ledgers are rewritten without bodies, and a deleted note restored on disk leaves it. The history rewrite `recall forget` prints also removes the ledger's past versions, puts the current one back, and passes `--force`, without which filter-repo refused to run.
