**Memory that reaches an agent unasked no longer carries commands, links or other chats' prompts.** A README or web page an agent read could become a note that session start injected into every later session. Now a rule that gives an agent something to act on (a URL or host, a command to run, a check switched off, private data sent somewhere) never loads at session start or mid-session, and neither does a note with such a title; a prohibition such as "never force-push main" still loads, and memory_search and read_note still find everything. A note whose rules only the agent stated is counted, not named, and rules a user turn stated without a typed quote are now marked `unverified`, so an unmarked rule means one from before speakers were recorded. Injected text keeps no `<` or `>` (each becomes ‹ or ›), so no note, rule, past chat or exploration report can open or close the block, and titles are one line of at most 120 characters. On my chats, session start loads 0.574 of the notes it must (was 0.576), 0.482 on held-out folders (was 0.488), holding back 13 of 733 rules. `recall status` redacts a chat's title and latest request before caching them or quoting them to other chats, and its cache rebuilds once. The deletion ledger (`.recall/notes.json`) kept the start of every note's body, and consolidation sent 200 characters of each deleted note to the model: it now keeps the title, scope and project, existing ledgers are rewritten without bodies, and a deleted note restored on disk leaves it. The history rewrite `recall forget` prints now commits the notes folder first (filter-repo's reset would discard uncommitted hand edits), deletes the listed notes from disk and history, also removes the ledger's past versions and puts the current one back, and passes `--force`, without which filter-repo refused to run.
