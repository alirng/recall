**An API key at its spend limit now falls back.** Anthropic answers a key past its monthly spend limit with a 400 ("You have reached your specified API usage limits"), which recall took for a broken setup rather than an empty account. A nightly run with `[model] fallback` set never switched to it, marked every chat failed, and logged "read 19 chats · 0 candidate memories". That reply now counts as out of credits: the run carries on with the fallback (or stops cleanly without one), and a batch an earlier run left running is kept for the next run rather than marked lost. The read step now logs why its calls failed and counts failed chats apart from read ones (`failed` in the run's counts), and Anthropic errors are logged in the API's own words rather than as the SDK's dump of the reply.
