**memory_search no longer rewrites the notes index on every call.** It used to drop and rebuild the notes tables each time, which took the index's write lock and changed its schema while other agents' servers were reading, so a search elsewhere could occasionally fail with a transient `vtable constructor failed` error. It now rebuilds only when a note file or the `[contexts]` in config.toml differs from what the index was built from, so a hand edit still shows up on the next search. A rebuild is one transaction, so readers never see half of one. A search that has nothing to rebuild now takes about 10 ms instead of about 125 ms with 700 notes.
