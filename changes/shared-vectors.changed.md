**Semantic search keeps one copy of the vectors, not one per agent.** Each agent session runs its own recall MCP server, and with embeddings on, each built a matrix of every message vector on its first search and kept it: over 100 MB a server for 23k messages, more than 1 GB with ten agents open. The vectors now sit in one file beside the index (`recall-vectors/`) that a server maps only while it searches, so the operating system holds one copy for all of them. Five servers after two searches each take 428 MB instead of 830 MB, and search ranks as before: search_v2 and SWE-CB were identical on a same-day paired run. `recall forget` rewrites the file without the forgotten chats. `recall embed` no longer runs twice at once and stops after 20 minutes (the next run carries on), finding the messages to embed reads only the chats that changed, and a search waits at most 10 seconds for the embedding model before going by words.
