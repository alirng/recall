**recall's hooks and tools answer faster.** On a history of 1,200 chats, the edit hook took 80 ms, 175 ms while other chats were working, and about 0.8 s with its cache gone, because before every edit it listed every agent's transcripts and read again in full each chat that had moved in the last 12 hours. Now it reads only what each recent transcript gained since its last look, and reads chats in full and asks git only when another chat touched the same file: 40 ms, and 150 ms cold. A chat that starts without recall's hooks (Codex before you trust them) is still seen at the next edit, from the folder its agent writes it to. One resumed in a transcript older than a day is seen within five minutes. When another chat has the file open, the git calls run side by side and skip macOS's `/usr/bin/git` stub (380 ms down to 150 ms). A prompt no longer waits on an Ollama model that is not loaded. Asking one started a load that Ollama dropped when the hook gave up, so every prompt waited a quarter of a second and the model never loaded. Now a background process loads it, at most once every 25 minutes, and a loaded model is waited for at most 100 ms rather than 250. Hooks that do not read the index load 15 ms less code. The MCP server reads the shell's rc files once per index refresh rather than three times, memory notes load eight times faster (`memory_search` 530 ms down to 165 ms), and a tool call waits for an index refresh only until it is a second old. A longer one, such as the rebuild after an update, carries on in the background. Until it is done, `search_chats`, `recent_chats` and `read_chat` say that chats may be missing. Refreshes commit after each chat they read, and the redaction scrub every half second, so a tool call that writes no longer waits tens of seconds for the index. One that would wait over 3 s answers from the notes or commit links as they stand.
