# recall: agent instructions

Python 3.11+, managed with uv. Runtime deps: `mcp` 2.x (`mcp.server.mcpserver.MCPServer`), `pyyaml`, `jsonschema`; `anthropic` is the optional `recall[anthropic]` extra.

- Run from the repo with `uv run recall <cmd>`. Hooks, the MCP server and the nightly job run the installed `recall-agents` release from PyPI, so changes here reach them only through a release; leave that install in place. Run commands that write notes or the index against a scratch copy (set `RECALL_HOME` and `RECALL_MEMORY`), because the installed release reads the same `~/.agents` folders and may not understand a newer format.
- Several chats edit this repo at once, so each task gets its own worktree on a branch off `origin/main` (`git worktree add .claude/worktrees/<topic> -b <topic> origin/main`), and all its edits stay inside it. Uncommitted changes in the main checkout belong to other chats: leave them as they are. Run `uv run recall status` before starting, and when recall reports another chat with open changes to a file you are editing, raise it with the user before going on.
- Before committing: `uvx ruff format src && uvx ruff check src` (CI pins the ruff version; match it when CI and local disagree).
- Extension points are in CONTRIBUTING.md. Read it before adding an agent source or a model provider.
- recall never assumes a model vendor. Provider choice lives in `config.toml` `[model]`; code paths go through `llm.build()` / `llm.from_spec()` and the `Provider` interface.
- The chat tables are derived from agents' files, but agents delete and rewrite those files, so recall also keeps its own copy of every chat it indexes (`chat_archive`, see `chats/archive.py`). That table, `forgotten_chats`, the memory tables and the notes are not derived: never drop them. Bump `CHAT_SCHEMA_VERSION` in `chats/store.py` when parsing changes: the chat tables rebuild from each agent's files, and chats no file yields any more come back from the archive. A parser change that should stop indexing some chats must also delete their archive copies, or the rebuild restores them. Anything that copies chats into the index or the archive must skip ids on `forgotten_chats`: an older release does not know that list and reads them back, and `forget.sweep` removes what it brought.
- A prompt change bumps the version line at the top of its file in `memory/prompts/`. Compare `uv run recall eval memory` before and after, averaging several `--fresh` runs: single runs vary by ±12 points.
- When search or memory misses something real, add a case to the personal evals in `~/.agents/recall/evals/` before changing code. Those files name real chats and stay out of the repo.
- Agents' chat history is read-only (`mode=ro` for SQLite): never write to Cursor's `state.vscdb`, `~/.codex/sessions` or `~/.claude/projects`. Only `recall install` touches agent settings files, and it backs each one up first.
- The index, notes, keys and eval sets hold private content. Never commit them or copy them into the repo.
- No unit tests. The checks are evals (`recall eval search`, and `longmemeval` / `locomo` for search changes) and running the CLI, MCP server and hook end to end.
